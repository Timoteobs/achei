Achei

Guia para replicar a API e o banco SQL Server em um ambiente de desenvolvimento local.

Objetivo

Ao concluir este guia, o desenvolvedor terá o banco Achei, os segredos locais e a API HTTPS funcionando, sem gravar credenciais no repositório.

BancoSQL Server com tabelas tbl_*.
SegurançaChaves AES e JWT distintas.
APICadastro, login e JWT disponíveis.

1. Pré-requisitos

  • .NET SDK 9.
  • Visual Studio 2022 atualizado, ou editor compatível com .NET 9.
  • SQL Server local e SQL Server Management Studio (SSMS).
  • Postman para testar a API.
  • Acesso ao repositório do Achei.
dotnet --version
dotnet --list-sdks

2. Preparar o código

Depois de clonar o repositório, abra um terminal na raiz e entre no backend:

cd .\achei\back-end
dotnet restore Achei.API.sln
dotnet build Achei.API.sln

Os avisos NU1900 indicam que o NuGet não conseguiu consultar dados de vulnerabilidade. Eles não impedem a compilação quando os pacotes necessários já estão disponíveis.

3. Criar o banco

  1. Abra o SSMS e conecte-se à instância local com uma conta autorizada a criar bancos.
  2. Abra achei\back-end\Data\Scripts\CreateDatabase.sql.
  3. Execute o arquivo completo.
  4. Atualize a pasta Databases e confirme a existência do banco Achei.
O script é idempotente. Ele cria o banco quando necessário e aplica somente migrations ainda não registradas em __EFMigrationsHistory.

As tabelas de negócio devem terminar com nomes como:

dbo.tbl_user
dbo.tbl_space
dbo.tbl_location
dbo.tbl_item

4. Criar um usuário SQL para a aplicação

Não utilize o login sa na connection string. Conectado ao SSMS com uma conta administrativa, escolha uma senha local forte e execute:

USE [master];
GO

CREATE LOGIN [achei_app]
WITH PASSWORD = 'SUBSTITUA_POR_UMA_SENHA_FORTE',
     CHECK_POLICY = ON;
GO

USE [Achei];
GO

CREATE USER [achei_app] FOR LOGIN [achei_app];
GO

ALTER ROLE [db_owner] ADD MEMBER [achei_app];
GO
Apenas para desenvolvimento: db_owner simplifica migrations locais. Em produção, use permissões mínimas e uma identidade gerenciada pelo ambiente.

Se o login ou usuário já existir, não recrie. Apenas confirme que ele possui acesso ao banco correto.

5. Configurar User Secrets

O projeto Presentation já possui UserSecretsId. Não execute user-secrets init e não grave chaves ou senhas no appsettings.json.

Gerar duas chaves aleatórias

Execute no PowerShell, dentro de achei\back-end:

function New-SecretKey {
    $bytes = New-Object byte[] 32
    [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
    [Convert]::ToBase64String($bytes)
}

$encryptionKey = New-SecretKey
$jwtKey = New-SecretKey

dotnet user-secrets set "Encryption:Key" $encryptionKey --project Presentation/Achei.csproj
dotnet user-secrets set "Jwt:Key" $jwtKey --project Presentation/Achei.csproj
Obrigatório: AES e JWT devem usar chaves diferentes. Nunca publique essas chaves em commits, tickets, prints ou mensagens.

Configurar a conexão com SQL Authentication

dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=SEU_SERVIDOR;Database=Achei;User Id=achei_app;Password=SUA_SENHA;Encrypt=False;TrustServerCertificate=True;" --project Presentation/Achei.csproj

Substitua SEU_SERVIDOR pelo mesmo nome usado no SSMS, por exemplo localhost, .\SQLEXPRESS ou o nome da máquina.

Alternativa com Windows Authentication

dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=SEU_SERVIDOR;Database=Achei;Trusted_Connection=True;Encrypt=False;TrustServerCertificate=True;" --project Presentation/Achei.csproj
Use Encrypt=True quando a instância local estiver preparada para TLS. Se ocorrer “requires encryption but this machine does not support it”, mantenha Encrypt=False somente no desenvolvimento local. Produção deve usar conexão criptografada.

6. Executar a API

Pelo Visual Studio

  1. Defina o projeto Achei / Presentation como Startup Project.
  2. Na lista ao lado do botão verde, selecione o perfil https.
  3. Não selecione Container (Dockerfile), a menos que o Docker Desktop esteja instalado.
  4. Pressione F5 ou Ctrl+F5.
  5. Quando solicitado, confie no certificado HTTPS de desenvolvimento para localhost.

Pelo terminal

dotnet run --project Presentation --launch-profile https

Endereços padrão:

https://localhost:7092
http://localhost:5022
https://localhost:7092/openapi/v1.json

Receber 404 na raiz / é esperado: a API não possui página inicial nem Swagger UI.

7. Validar no Postman

Cadastrar um usuário

POST https://localhost:7092/api/auth/register
Content-Type: application/json

{
  "name": "Usuário Teste",
  "email": "teste.achei@local.dev",
  "password": "Teste@123456",
  "confirmPassword": "Teste@123456"
}

Resultado esperado: 201 Created, dados do usuário e accessToken.

Efetuar login

POST https://localhost:7092/api/auth/login
Content-Type: application/json

{
  "email": "teste.achei@local.dev",
  "password": "Teste@123456"
}

Resultado esperado: 200 OK e um JWT com três partes separadas por pontos.

Validar senha incorreta

Repita o login com outra senha. O resultado esperado é 401 Unauthorized em formato application/problem+json.

Conferir o hash no banco

USE [Achei];

SELECT [id], [name], [email], [password_hash], [active]
FROM [dbo].[tbl_user]
WHERE [email] = 'teste.achei@local.dev';

O valor deve começar com $argon2id$ e nunca ser igual à senha informada.

8. Atualizar um banco existente

Para um banco criado anteriormente, execute novamente o arquivo atualizado Data\Scripts\CreateDatabase.sql. O histórico impede a reaplicação de migrations concluídas.

Quem trabalha diretamente com migrations pode instalar a ferramenta compatível e atualizar o banco:

dotnet tool install --global dotnet-ef --version 9.0.20

dotnet ef database update --project Data --startup-project Presentation

Antes de criar uma nova migration, atualize o código e confirme que a última migration do repositório já foi aplicada.

Checklist final

  • O build conclui sem erros.
  • O banco Achei existe e contém tabelas tbl_*.
  • Encryption:Key e Jwt:Key existem, são Base64 de 32 bytes e são diferentes.
  • ConnectionStrings:DefaultConnection aponta para o banco correto.
  • A API inicia pelo perfil https.
  • Cadastro retorna 201 e login retorna 200.
  • A senha está armazenada como hash Argon2id.
